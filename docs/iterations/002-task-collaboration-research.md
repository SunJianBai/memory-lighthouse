# 002 调研：家庭待办的负责人和筛选

调研日期：2026-09-20。仅核对公开的一手资料，未登录体验竞品；下列能力不代表已在记忆灯塔实现。

## 竞品证据

- **Caring Village**：开发者发布的应用说明明确支持创建任务、分配给照护圈成员，以及家属主动认领责任；官网共享日历介绍也说明成员可以自愿承担任务。[开发者应用说明](https://apps.apple.com/us/app/caring-village-caregiver-app/id1093814557)、[官网功能介绍](https://caringvillage.com/partners/adria-thompson)
- **Lotsa Helping Hands**：官方帮助说明，日历区分“仍可报名”“需求已满足”“自己已报名”的日期；成员查看具体任务后报名，系统向本人和协调者发送确认。当前官网仍介绍发布帮助需求、成员自愿参与和自动提醒。旧帮助页可能不完全对应当前界面，不能据此断言现有筛选按钮的名称。[官方任务帮助](https://agis.lotsahelpinghands.com/help/pe_activities.html)、[当前产品说明](https://lotsahelpinghands.com/how-it-works)

## 推导的用户需求

以上证据支持“看清分工、找到自己承诺的事项”，不证明某种设计一定降低遗漏率。针对已有认领流程，建议验证：家属是否能迅速回答“谁在处理”“哪些无人处理”“我还有什么未完成”，避免把“已认领”误解为“已完成”。

## 建议范围（待代码可行性核对）

在现有家庭待办区域增加“全部未完成／待认领／我负责／已结束”筛选；卡片显示负责人姓名及“我负责”标记，不暴露账号邮箱。保留明确的“认领”“完成”“不再处理”操作；成功后刷新分组，版本冲突时说明任务已变更并重新读取。切换家庭或长者清空旧列表；无权限、加载失败和筛选结果为空分别呈现。

沿用现有状态机和服务端授权，不把前端筛选当权限边界。此轮不加入自动派单、强制转交、催办推送、任务聊天或医疗判断；不根据竞品营销文案推断这些能力。若负责人已退出家庭，名称应安全降级而非显示内部 ID，具体历史姓名策略需在需求设计中确定。
