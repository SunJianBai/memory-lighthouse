# 007：照护记录可读性与时区一致性

日期：2026-09-20；本轮起点 `8de3879`。仅本地开发、验证和提交，不推送、部署或操作生产数据。

## 1. 需求与依据

依据[官方资料与源码调研](007-care-history-readability-research.md)，家属需要直接读懂提醒状态、动态来源与发生时间；异地家属不应因设备时区不同看到无标识的另一日期。

本轮仅调整 Web 日程页和 Android 照护页的“提醒记录／最近动态”。时间统一使用**当前所选长者档案时区**，不是承诺还原记录创建时的历史时区。既有字段已足够，无 API 或数据库迁移；服务端现有状态机、权限、排序和核验流程保持不变。

## 2. 页面设计

- 两端区域名称统一为“提醒记录”“最近动态”，加载和空态不再使用“实例／事件”等实现术语。
- 每个区域标示长者时区，时间完整显示 `yyyy-MM-dd HH:mm`；Web 使用带有效绝对时刻 `dateTime` 的语义化 time 元素。长时间和标题可以换行，不与状态标签争抢一行。
- 提醒状态：DUE→待提醒、AWAITING_CONFIRMATION→待本人确认、NEEDS_FAMILY_REVIEW→待家属核验、CONFIRMED→已确认、EXPIRED→已关闭。只有 CONFIRMED 使用成功语义；EXPIRED 不等于完成，待核验不等于已知未完成。
- 来源：FAMILY→家属、RECIPIENT→本人、ROUTINE_SCHEDULER→日程提醒、COMPANION_DEVICE→陪伴设备。
- 动态类型：ROUTINE_CONFIRMED→日程确认、ROUTINE_NOT_CONFIRMED→未完成核验、ROUTINE_CONFIRMATION_MISSING→待核验提醒、RECIPIENT_REQUESTED_FAMILY_CONTACT→联系家人请求。
- 级别：INFO→一般记录、ATTENTION→需关注。未知状态、来源、类型、级别分别使用“状态未知／来源待确认／其他动态／级别未知”，不泄露内部编码，不推断医疗风险。保留服务端原有中文标题和摘要。
- 无效或缺失时间显示“时间未知”；缺失时区显示“时区未设置”，无效时区显示“时区无效”。不能回退为查看者当地时区或伪造 UTC；不能因此崩溃或开放新的操作。
- 保留既有核验按钮、确认、权限失败、独立加载和工作区迟到响应保护。Android 保持原生 Compose，不全局改写其他页面的时间工具。

## 3. 实施计划与可行性

1. 两端各增加一个小型照护记录展示模块，集中映射与显式时区格式化；不引入通用国际化框架或依赖。
2. 接入真实提醒与动态区域；Android 提取动态卡片便于实际组件测试，提醒卡片保持既有操作回调。
3. Web 单测覆盖全部映射、未知值、无效输入、跨年／跨午夜／夏令时和真实页面切换长者；Android 做相同纯函数测试与 Compose 卡片测试。
4. 服务端运行既有提醒状态机／照护流程回归，核实关闭与核验语义没有变化。Web 构建及实际浏览器、Android 单测／构建及隔离模拟器实际应用验证。原 Android 应用不清空，不使用生产数据。
5. 固定起点双轴审查，修正可确认问题，记录实际测试和未覆盖范围，最后本地 Git 提交。

## 4. 验收标准

- 已知编码不再裸露；未知编码中性降级；关闭不呈现为成功。现有核验及待办流程不受展示重构影响。
- 同一绝对时刻在指定长者时区下得到一致的年月日时分；覆盖上海／洛杉矶、跨年、夏令时变化；默认设备时区不能影响结果。
- 切换长者时区域时区和记录一起更新，旧请求不能污染新工作区。时间／时区失败明确显示而非本地回退。
- 真实 Web 页面和原生 Android 页面均验证并记录证据；单纯编译或纯函数通过不代表实际界面已验证。小屏、长标题和字体缩放按可执行范围验证，未执行项保留说明。
