# 006：家庭待办主动释放

日期：2026-09-20。本轮起点 `c349377`。仅本地开发、测试和提交，不推送、不部署、不操作生产数据。

## 1. 用户需求与范围

依据[官方调研及源码核对](006-task-handoff-research.md)，已认领待办的家属可能无法继续处理，需要把同一事项交回待认领，而不是假装完成或忽略。首轮先实现本人主动释放。OWNER 回收明确 LEFT 成员任务的权限已向用户询问，在确认之前不实现。

只允许当前家庭的活跃成员、仍有该长者 VIEW_EVENTS 权限、且为 CLAIMED 任务的当前负责人执行释放。OPEN、已完成和已忽略任务不能释放；他人的任务不能释放。身份、家庭、长者、状态和版本全部由服务端验证。

## 2. 页面与行为

- Web 日程与待办、Android 照护页：本人已认领的卡片增加次要按钮“交回待认领”。不占用“完成”主按钮，不更改已有筛选、结果备注和日程操作。
- 点击后展示卡片内确认：“交回后将不再由你负责，其他有权限的家属可以认领。此待办仍未完成。”提供“确认交回”“取消”；取消不发请求并恢复焦点。Web 复用现有卡片内确认，Android 使用原生 Compose；按钮保持 44px / 48dp。
- 同一卡片只允许一个确认区域；列表刷新、版本变化或工作区切换后，旧确认不可提交。请求期间禁用相关操作，重复点击不重复执行。
- 成功后重新读取权威看板；同一任务变为 OPEN，负责人为空，“我负责”减少、“待认领”增加；在“我负责”下任务自然消失。失败及冲突不假装成功，刷新实际状态并提示。保留原有跨用户／家庭／长者的迟到响应保护。
- 新客户端遇到旧服务端缺少能力字段时安全降级为无释放按钮，旧客户端继续使用原三个命令。不存在“释放等于已完成”的转换。

## 3. 代码可行性与契约

已有 FamilyTask 的可空负责人、版本和状态，以及 FamilyTaskAction 的字符串动作、前后状态、操作者和幂等键，无需数据库迁移。新增 POST `/households/:householdId/family-tasks/:taskId/release`，请求沿用 `{ version }` 和 `Idempotency-Key`；不接受新的负责人或结束结果。看板增加 `canRelease` 布尔能力字段。

复用现有 Serializable 事务、命令指纹和加密回执；当前授权校验仍在幂等回放之前。变更为 CLAIMED → OPEN、负责人置空、版本加一，保留来源、优先级、截止时间及未完成语义；不生成完成时间或处理结果。事务内追加 RELEASE 动作与 `family-task.release` outbox，只有实际成功变更才记账。本人释放的操作者就是前负责人，无需把个人信息写入明文备注。

客户端继续使用现有 careCommands 幂等机制以及服务端看板重读。Android 扩展 Repository → ViewModel → FamilyUiActions → 卡片链路；沿用 recipient 操作作用域与成功／失败后的重同步，不直接把旧命令响应当完整看板。

## 4. 实施和验收

1. Server：状态机、命令、HTTP、看板能力；验证本人释放、他人拒绝、权限撤回、家庭／对象隔离、版本冲突、重复命令只记一次、释放后重新认领与完成兼容。
2. Web：能力解析兼容旧接口、卡片确认取消、版本变化保护、操作后重读与筛选计数；真实页面回归和构建。
3. Android：DTO 默认拒绝、Repository 幂等、ViewModel 范围及刷新、卡片确认；单测、隔离 `.iterationtest` 模拟器实际主界面和真实本地 API。
4. 隔离 MySQL HTTP 测试与实际浏览器，确认任务未结束且另一成员能认领；保留失败证据。最后独立规范／需求审查、本地提交。
