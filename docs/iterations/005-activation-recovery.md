# 005：设备激活结果与恢复

日期：2026-09-20。基线 `d1948c7`。仅本地开发、测试和提交，不推送、不部署、不操作生产数据。

## 1. 依据与诊断

沿用[官方调研](005-activation-recovery-research.md)。用户需要明确知道当前等待谁、是否已经完成，以及下一步在哪里操作。成功绑定不等于媒体、模型或心跳可用。

真实页面回归 `CompanionPage.activation.test.tsx` 固定时钟并只替换请求和媒体边界：一次 `ACTIVATION_ALREADY_CONSUMED` 冲突后，下一次查询返回 `CONSUMED` 和恢复证明，真实页面完成 exchange、context 与 pending 清理。连续两次测试均在“旧错误应消失”断言失败。最小序列没有并发请求，凭据与 context 已成功，支持“激活错误与运行错误共用状态且成功未清除”的原因。该测试证明可重现代码路径，不代表已还原此前浏览器现场的原始网络顺序。

## 2. 需求及页面设计

1. 家属端将所有激活状态显示为中文阶段和对应下一步。完成、过期、取消、次数耗尽后不再展示可用二维码、旧码或取消按钮；完成可“继续添加设备”，失败终态可“重新生成激活码”，都必须显式操作。
2. 激活状态查询错误和提交错误分开；后续权威查询成功仅清理已过时的同步错误，不清除其他操作错误。审批详情读取失败时不能保留可批准的旧快照。绑定列表刷新失败单独在列表显示并可重试，不能把已完成激活标为失败。
3. 家属轮询单次在途、按激活与工作区世代持有归属；慢于两秒的响应仍可被采纳。审批、取消、换家庭/长者、卸载后旧响应无权写回。禁止用每次 interval 的 latest-wins 造成永久饥饿。
4. 陪伴端将激活错误与运行错误分开。恢复成功仅清除激活错误，凭据落盘前不宣称成功；继续保留安装证明、有限冲突重试和持久化失败恢复句柄。
5. 已持有设备凭据而上下文暂时失败时，不再提供重复绑定表单；显示“设备已激活，信息暂未同步”和显式重试。状态与心跳失败单独表达，不宣称当前在线，不删除凭据。等待家属批准显示正常进度，不显示英文枚举。
6. 保留服务端审批快照、幂等、当前授权复查、恢复证明、撤销与轮换防护。Android 验证已有激活所有权和恢复逻辑，仅出现可复现差异时修改；不为三端覆盖而改动正确协议。
7. 浏览器的家庭选择、本地偏好等无关存储事件不重新初始化已激活设备，不重复撤销另一标签页的家属会话。显式进入设备模式时仍必须退出家属身份；退出失败不得开始读取设备信息、心跳或来电轮询。

沿用现有 React/Compose、配色、卡片与按钮；错误邻近操作并使用 alert，进度使用 status，按钮至少 44px / 48dp。无需弹窗、宣传文案或新增设计系统。终态保留简短结果，凭据不继续显示。
