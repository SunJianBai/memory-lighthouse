# 004：陪伴启动检查

日期：2026-09-20。开发基线：`0b2e16a`。仅本地开发、测试与 Git 提交，不推送、不部署、不修改生产设备。

## 1. 需求与非目标

依据 [调研](004-companion-readiness-research.md)，将“已激活”“权限允许”“授权有效”“模型配置已提供”分别表达，帮助在陪伴设备上排查无法开始对话的问题。现有 Android 将三个系统权限合并显示为“设备已就绪”，Web 缺少启动前的分项说明；两者均不能证明实际采集或模型连通。

验收需求：

1. 已激活的 Web、Android 陪伴端提供“启动检查”，明确检查的是此浏览器／此 Android 设备，不推断家属手机或远端设备的系统权限。
2. 展示设备身份与服务端本次检查时间、家庭音频与视频陪伴授权、模型配置、本机麦克风／摄像头权限。Android 通知权限单独提示，不将其等同于模型或媒体是否可用。
3. Server 新增设备身份认证的只读 `GET /device/readiness`：实时检查有效绑定和最新授权，区分 AUDIO 与 AUDIO_VIDEO 的缺失授权；仅报告模型配置是否完整，不探测远端模型，不返回模型地址、密钥、记忆或对话。复用现有启动授权规则，无数据库迁移。
4. “检查启动条件”只读取状态，不弹出媒体授权框、不录音录像、不创建会话、不抢占家属通话。未检查、查询不支持、查询失败、明确拒绝分别展示；浏览器不支持权限查询时保留真实的“开始陪伴时按提示授权”路径。
5. 对缺少家庭授权提示家属端“隐私与授权”；系统权限问题显示本端设置说明，Android 复用授权／系统设置按钮；配置异常提示联系管理员。保持现有开始陪伴入口和服务端实时鉴权，不用检查结果代替授权或绕过媒体互斥。
6. 检查显示加载、错误及重试；新检查清除旧成功结果。服务端结果最多作为 60 秒内的参考，超过后明确“需重新检查”；从请求开始保守计算有效期，包含传输耗时，不依赖客户端和服务器墙钟一致。离开前台、换绑定、卸载组件使旧结果失效，迟到响应不得覆盖新设备／新一轮状态。网络失败不能继续显示本次检查成功。
7. 两端明确“权限允许不代表采集成功；模型配置已提供不代表连接成功”。说明保持简短，详细限制放在指南；默认不堆技术协议名或后台实现说明。

非目标：实际音视频采集自测、录音回放、扬声器测试音、远端系统权限上报、模型探测会话、网络测速、自动修复配置、重建媒体链路。实际采集和模型连接仍由用户启动陪伴后执行；不能以本轮结果宣称硬件正常、模型在线或通话质量达标。

## 2. 页面设计

- Web：在激活状态和陪伴操作区之间增加可展开“启动检查”；使用现有卡片、按钮和语义颜色，列表每项有标题、文字状态及必要的下一步。窄屏单列，按钮至少 44px；检查不移动焦点或滚动到别处。
- Android：用同主题、默认折叠的启动检查卡替代笼统的“设备已就绪”卡。“检查启动条件”放在展开区顶部，先操作、后阅读分项结果。使用 Compose 原生控件、至少 48dp 按钮；内容可随大字体纵向展开。授权按钮保留显式动作，返回系统设置时重新读取本机权限并使之前服务端检查过期。
- 仅显示当前检查的证据：服务端成功响应代表当时可访问且身份有效；模型一栏写“配置已提供，连接未检查”，不标“模型已连接”。音频与视频授权分开显示，摄像头未授权不误报音频也被拒绝。
- 指南补充“设备已激活，但无法开始陪伴”步骤：在陪伴设备检查 → 按项目处理 → 重新检查／开始，保留关闭网页不保证提醒的既有限制。

## 3. 实际代码可行性

- Server `CompanionSessionApplicationService.requireBindingContext` 已核对设备、家庭、长者、绑定版本与撤销状态；`captureConsent` 读取当前授权。新只读方法不调用 `buildCareSnapshot`，避免无关记忆解密和返回内容。`missingRuntimeConsent` 的三个运行时授权范围可复用为纯规则。
- Web `deviceSession` 已有带设备令牌的请求入口；新增只读方法。独立检查组件持有请求代次和本次结果，绑定 ID 作为组件身份；不侵入 `CompanionStartLifecycle` 或媒体所有权。浏览器权限查询独立超时并降级未知，不调用 `getUserMedia`。
- Android Repository 已有设备请求通路；增加强类型返回。检查状态与请求所有权独立于家庭页面加载和媒体心跳；UI 生命周期失效检查结果，不将失败写成全局已就绪。沿用已有权限读取与授权回调。
- 无新数据库表、依赖、后台轮询或生产服务配置。每次检查为一个只读接口；检查不更新设备在线时间，也不延长会话租约。

## 4. 开发和验证计划

1. Server：纯规则与只读接口；单测覆盖音频／视频差异、默认拒绝、无效绑定、无效配置及不泄露敏感信息；隔离 MySQL HTTP 测试验证真实设备身份、授权撤回及无写入。
2. Web：API 类型、查询工具和独立组件；测试拒绝／未知／异常、迟到响应、过期、前后台及绑定切换、重试和不请求采集；桌面与 375px／横屏实际检查。
3. Android：Repository、状态所有权、Compose 卡片与生命周期；单测与 API 合约测试；本地隔离包模拟器验证检查、拒绝、重新授权／设置返回、显示和旧概览／待办／日程流程。
4. 三端回归和构建、记录实际失败与限制、双轴审查、本地提交。浏览器与模拟器不调用生产模型；检查成功不当作真正模型对话成功。

### 验证边界

- 未发起实际模型、音视频或 LiveKit 连接，不能据此宣称模型在线、硬件可采集或通话质量合格。
- Android 真页面使用当前未允许的摄像头／麦克风权限；后台恢复使用 Activity 生命周期切换验证，系统授权弹窗及系统设置页逐项操作未做人工验收。授权按钮触发与不自动采集由组件测试覆盖。
- 浏览器实际联调观察到一个既有现象：激活成功后仍可能残留“激活请求已经结束，不能重复使用”提示；本轮未修改激活业务，列入下一轮诊断候选。
- 官方测试同步说明仅用于诊断方法核对：[Compose 测试同步](https://developer.android.com/develop/ui/compose/testing/synchronization)。最终通过证据来自本地真实触摸和 HTTP 行为，不来自文档推断。
