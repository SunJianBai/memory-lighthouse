# 008 照护记录历史查询

日期：2026-09-20；实施基线：`d4116ee`。依据[官方调研与源码核对](008-care-history-navigation-research.md)。状态：规格已确定，开发中；未完成三端验收。

## 需求与非目标

家属能够在当前长者的提醒记录、照护动态中查找更早记录，按日期缩小结果并连续加载。不能只筛选客户端已下载的前 30 条。保留近期未来提醒、原核验命令、中文状态、长者时区和家庭待办。

只查询已存储、当前有权限的数据。提醒按计划时间和当前状态查询，正文仍来自当前日程；动态按发生时间查询。没有记录不代表没有行动，“已关闭”不代表已完成。不新增全文搜索、跨长者汇总、正文快照、导出、通知、AI 判断或留存承诺，不处理未获确认的 OWNER 回收待办。

## 页面与交互

- Web 日程页与 Android 家属照护页沿用两个记录区域，不新增导航层级。提醒默认范围保持服务器当前时间前 24 小时至后 7×24 小时；动态默认最新一页，能继续加载更早动态。
- 两个区域分别提供“查询历史”折叠表单：开始日期、结束日期、查询；提醒另有“状态”（全部、待提醒、待本人确认、待家属核验、已确认、已关闭）。草稿不改变现有结果，提交才应用。默认草稿为长者当地今天及前 6 天。
- 使用原生日期控件；Android 保持 Compose，不引入 WebView。起止日期包含结束日，单次最多 31 个自然日，可选更早月份。这是查询跨度限制，不是只保留 31 天。时区沿用当前长者档案。
- 展示已应用范围、时区及“已加载 N 条”；“加载更多”一次只发一个请求。最后一页显示“本次查询已加载完”，不能将已加载数量称作全量总数。范围内无数据与请求失败分开显示。
- 筛选后提供“恢复近期”（提醒）／“恢复最新”（动态）。刷新保持已应用条件、重新载入第一页；核验成功后分别按两个区域当前条件刷新，不退回默认范围。待核验筛选中已确认项自然退出。
- 条件或长者切换立刻清除旧结果、cursor、错误与加载状态；拒绝旧请求成功或失败写回。分页途中普通网络错误保留已加载项、允许重试；401/403/404 清除受保护结果并显示错误。新查询失败不伪装成空结果。
- 筛选区使用显式标签，Web 正文／输入至少 16px、交互目标至少 44px，Android 至少 48dp；小屏纵向换行，状态不单靠颜色区分。

## API 契约

新增只读端点，旧数组接口完全保留：

```
GET /households/:householdId/care-recipients/:recipientId/occurrences/history
GET /households/:householdId/care-recipients/:recipientId/events/history
```

查询参数：`startDate`、`endDate`（必须同时提供，严格 YYYY-MM-DD、真实日期、含首尾最多 31 天）；`limit`（整数 1–50，默认 30）；`cursor`（不透明，最多 4096 字符）。提醒另接受 `status` 五种枚举，动态不接受状态。未知参数按现有全局校验拒绝。

不传日期：提醒采用前 24 小时至后 7 天的滚动窗口；动态无日期过滤，但始终有分页上限。传日期：服务端读取长者时区，转换为 `[开始日边界, 结束日次日边界)`，不假设自然日为 24 小时；整日被时区跳过时允许得到空日窗。限制日期年份 1900–9998，避免超出接口四位年边界。

返回：`{ items, nextCursor, timezone, from, to }`。`from/to` 为实际 UTC 半开窗口，无界动态为 null；`nextCursor` 无后续时为 null。每次分页重新鉴权，按时间降序、ID 降序稳定续查；数据库先过滤且 `take = limit + 1`，只投影／解密返回页的记录，不查询总数。

游标使用现有 AES-GCM 内容加密接口认证，载荷有专用版本标记，绑定家庭、长者、记录种类、当前档案时区、日期、状态、limit 与实际窗口，并携带最后一条的时间、ID。篡改、不同条件或跨作用域返回 400；每页原 VIEW_EVENTS 权限仍是访问边界。近期窗口由第一页固化到 cursor，避免翻页时随时钟漂移；刷新无 cursor 则重新计算。游标不承诺跨加密密钥轮换有效，失效后重新查询。

这些分页是实时查询，不是多页事务快照。翻页间新增记录刷新后可见；状态发生变化可能离开筛选。旧数组端点仍可能无界读取，本轮不声称消除其所有开销。
