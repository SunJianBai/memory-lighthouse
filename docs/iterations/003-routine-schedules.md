# 003：提醒周期与日期范围

日期：2026-09-20。上一轮基线：`97343d2`。本轮只本地开发、验证、提交，不推送、不部署、不修改生产数据。

## 1. 使用场景与需求

依据 [官方产品调研](003-routine-schedules-research.md)，家属需要区分一次预约、每天生活事项和指定星期的活动，并在保存前确认“哪一天、什么时间、持续多久”。不以竞品说明证明本产品已实现。

验收需求：

1. Web、Android 均支持单次、每天、周一至周五、周末、自选星期；星期一至五不等于法定工作日。
2. 单次选择日期；重复选择开始日期和可选结束日期。日期上下界均包含。至少选一天，拒绝非法日期、结束早于开始、有限区间中没有选中星期。时区明确显示，默认日期按长者时区计算。
3. 表单实时展示中文摘要；列表显示相同规则、时间、日期范围与时区。无结束日期写明“持续重复”，不把已过期的日期范围写成仍会执行。
4. Web 补齐编辑入口；Android 保留编辑。修改整条规则，不提供“仅这一次”的虚假选项。使用服务端版本检查；保存失败保留输入；切换对象后旧表单和旧响应不得影响新对象。
5. 单次日程在调度窗口内仅生成一次，重复运行不重复；重复只在所选星期和有效范围触发。单次遇到不存在的夏令时时刻明确拒绝，重复规则沿用现有跳过该时刻规则。
6. 保留服务端授权、加密和版本检查。相同日程规则重存不创建新调度版本；真正变更才停用旧规则、创建新版本，避免仅编辑标题也改变调度身份。
7. 解释确认等待和家属待办延迟，修正 Android“提前通知家属”的错误文案。不要承诺系统通知送达或自动医疗判断。

## 2. 页面设计

- Web 日程卡片增加规则摘要和“编辑”按钮，状态采用正式中文；新增/编辑为页面内表单，字段分组：内容、提醒时间与周期、日期范围、确认设置。星期按钮可换行且可键盘操作，错误放在表单内；提交期间禁止重复提交，保留取消入口。
- Android 沿用原生 Compose 对话框与主题。周期快捷项和星期按钮分行排列，避免必须横滑才发现星期日。日期用原生日期选择器，也保留清晰格式；摘要在保存按钮前可查看。复杂确认设置与简短说明集中呈现，所有主要按钮至少 48dp。
- 编辑提示：“修改整条日程规则；已确认及已产生的家庭待办会保留。”旧规则的未完成提醒会按现有调度流程结束，不承诺修改历史事项。
- 不新增周日历、隔周/月度、法定节假日、单次例外、日历同步；这些不是完成本轮已承诺功能的替代项。

## 3. 代码可行性

- `RoutineSchedule` 已有 weekdayMask、startDate/endDate、timezone，无需迁移。Sunday 为最低位，周一至五为 62，周末为 65；同一天上下界即可表示单次。
- `domain/schedule-time.ts` 已实现时区转换、包含日期边界、窗口左闭右开及确定性 occurrence ID。重复 DST 缺口跳过、重复小时取较早 UTC 时刻。需补范围可触发校验与单次缺口校验。
- `updateRoutine` 当前只要传 schedule 就停用旧版并创建新版，需比较实际字段；旧版 DUE/AWAITING_CONFIRMATION 在 `advanceOccurrences` 中变为 EXPIRED，其他历史状态与已产生待办保留。不是历史快照编辑功能。
- Web 现有创建写死 127，无编辑 UI；可抽出复用编辑器和规则格式化/校验，继续使用页面已有 scope/epoch 归属检查与 REST 接口。
- Android 已有完整字段与编辑命令，可集中校验和摘要，修正设备时区默认日期、日期范围校验与通知标签，保留 Native/Compose 技术栈。

### 失败与修正

- Android 旧流程等待“已结束 2”曾超时。接口实际已完成并保存备注，截图证明懒加载列表的筛选栏不在屏内。第一次滚动补丁的模糊匹配又误中了“已结束的提醒”日程标题；改为稳定的 `family-task-filters` 标识后，全量 19 项通过。测试保留失败截图及语义树输出，未放宽数量断言。
- Web 更新指南后，原有“关闭页面不保证提醒”的边界断言失败；恢复明确限制后全部 218 项通过，没有删除测试。
- Web 实机发现列表底部点击编辑后表单仍在屏幕外；新增标题焦点与定位，组件测试及浏览器复验通过。
- 审查复现：同日起止、原星期掩码为 62 的规则，仅改标题时客户端会改发 127，导致服务端创建新调度身份。Web 与 Android 的回归测试先失败，再修正为日期未变时保留原掩码；新建或改为其他日期的单次规则仍使用 127。两端测试均转为通过。
- 审查复现：编辑缺少幂等键，响应丢失后重试会因旧版本冲突而无法确认结果。两端接入已有持久化命令重试机制，服务端在同一事务保存加密回执，重放前重新检查权限。新增并发测试先因串行化冲突返回 500；复用有次数上限的事务重试后，同键请求都返回 200、仅升一次版本，不同内容复用同键返回 409，越权请求返回 403。
