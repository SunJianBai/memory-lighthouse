# 产品与用户流程

## 产品命题

“守忆灯塔”不做一个等待提问的聊天框，而做一个有边界的日常任务陪伴层：家属先提供可信事实，确定性规则决定何时需要处理任务，MiniCPM-o 4.5 负责在真实场景中看、听、说并允许长者随时打断。

核心价值不是“AI 替人做判断”，而是降低轻度认知障碍长者完成日常步骤时的记忆负担，并把无法确认的事项平稳交还给家属。

## 三类用户

| 用户 | 核心需求 | 界面策略 |
| --- | --- | --- |
| 长者 | 少记步骤、少被责备、能随时打断 | 大字号、一个主任务、四个明确动作、自然语音 |
| 家属 | 看见是否确认、维护可信资料、保留最终决定权 | 家庭概览、记忆、日程、设备、授权和远程关怀 |
| 管理员 | 维护系统运行、审计开发期内容访问 | 独立管理员面板、最小权限和全程审计 |

## 首次设置流程

1. 家属使用邮箱或用户名和密码注册，输入邮件中的 6 位验证码完成邮箱验证。
2. 创建家庭与陪伴对象，录入日常称呼、时区、家庭位置标签和必要的沟通偏好。
3. 邀请其他家庭成员，并按角色分配记忆、日程、设备和远程协助权限。
4. 在服务器记忆档案与日程页面录入经家属确认的事实和安排，再逐项确认摄像头、麦克风、模型处理、记忆存储与远程协助授权。
5. 通过二维码或动态激活码绑定一台陪伴设备；设备取得独立身份后进入锁定的陪伴模式。

不会要求身份证号、银行卡、诊断结论等与日常陪伴目的无关的信息。

## 日常使用流程

### 家属准备

1. 在“记忆档案”中添加称呼偏好、常用物品位置、重要人物等可验证事实；修订与删除均保留可追溯记录。
2. 在“日程与待办”中录入时间、标题、操作说明、确认问题和家属通知窗口；药物相关内容只复述家属已确认的信息。
3. 在“陪伴设备”中生成二维码或动态码，批准设备绑定并确认一台设备只对应一位长者。
4. 在“隐私与授权”中逐项核对有效授权；人物或图片资料不用于人脸自动认证。

### 长者陪伴

1. 已激活设备读取服务端下发的最小陪伴上下文；点击“开始陪伴”后才按有效授权申请摄像头和麦克风。
2. 服务端日程实例进入执行窗口时，规则层触发提醒并使用幂等键防止重复处理。
3. 模型根据当前画面、语音和已录入事实，用最多两句话给出一个步骤。
4. 长者可随时自然说话打断模型；“完成了”“再说一遍”“联系家人”都有大按钮。只有会返回用户转写的本地 Provider 才额外启用对应语音命令；ModelBest 官方双工协议没有用户转写事件，因此不拿模型回复冒充可审计的本人确认。
5. 画面不清、标签不一致时系统不猜测；提醒超过家属设置的等待时间仍无明确确认，自动转入待家属查看。

### 家属闭环

1. 家属端只显示可解释事件，如“本人已明确确认”“需要家属查看”。
2. 摘要明确区分用户确认、模型提示和家属操作。
3. 待办可由家属人工认领、确认并关闭；原事件与家属回执都保留来源，没有医学或危险结论。
4. 家属发起远程关怀时，陪伴端必须现场接听；通话固定不录音、不转写，结束后释放摄像头和麦克风。

```text
│  ├─ 记忆档案
│  ├─ 日程与家庭待办
│  ├─ 陪伴设备激活与绑定
│  ├─ 隐私与授权
│  ├─ 远程关怀通话
│  └─ 账号与安全
├─ 陪伴设备模式
│  ├─ 设备激活
│  ├─ AI 陪伴与当前任务
│  └─ 现场接听远程关怀
└─ 管理员面板：账号、家庭、设备、审计与开发期内容检查
```

## 完整产品演示成功标准

- 观众能在 30 秒内理解对象、痛点和边界。
- 使用真实账号展示注册验证、家庭与陪伴对象、服务器记忆和日程、设备激活及角色隔离。
- 在陪伴设备上呈现主动提醒、用户打断、记忆调用和家属协同，并在家属端看到来源明确的结果。
- 家属远程呼叫只有在陪伴端现场接听后才建立媒体连接；拒接、挂断和 AI/远程接管状态均可解释。
- 模型或网络失败必须显示真实失败状态，不伪造医学判断、“危险告警”或已经完成的业务结果。
