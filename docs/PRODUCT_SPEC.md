# 产品与用户流程

## 产品命题

“守忆灯塔”不做一个等待提问的聊天框，而做一个有边界的日常任务陪伴层：家属先提供可信事实，确定性规则决定何时需要处理任务，MiniCPM-o 4.5 负责在真实场景中看、听、说并允许长者随时打断。

核心价值不是“AI 替人做判断”，而是降低轻度认知障碍长者完成日常步骤时的记忆负担，并把无法确认的事项平稳交还给家属。

## 三类用户

| 用户 | 核心需求 | 界面策略 |
| --- | --- | --- |
| 长者 | 少记步骤、少被责备、能随时打断 | 大字号、一个主任务、四个明确动作、自然语音 |
| 家属 | 看见是否确认、维护可信资料、保留最终决定权 | 状态摘要、事件时间线、日程和第一联系人 |
| 演示者 | 稳定呈现全模态能力和业务闭环 | 五步导演台、演员提示、指标区、回放/真模型明确区分 |

## 首次设置流程

1. 录入长者姓名、日常称呼、生日、家庭位置标签和沟通偏好。
2. 录入第一联系人、关系、电话和事件查看权限。
3. 分别确认本地存储、摄像头、麦克风、敏感记忆和公网处理边界。
4. 完成后进入记忆中心，继续补充药物日程、人物照片和生活记忆。

不会要求身份证号、银行卡、诊断结论等与演示无关的信息。

## 日常使用流程

### 家属准备

1. 在“药物与日程”中录入药物别名、时间、容器标签、存放位置和家属确认过的要求。
2. 上传的是“药盒标签资料”，不是用于训练药片识别器的样本。
3. 在“生活记忆”中添加眼镜位置、沟通偏好等可验证事实。
4. 在“人物与称呼”中上传家属照片只用于资料展示；Demo 不做人脸自动认证。

### 长者陪伴

1. 点击“开始陪伴”后才申请摄像头和麦克风。
2. 日程进入宽限时间窗口时，规则引擎触发提醒。
3. 模型根据当前画面、语音和已录入事实，用最多两句话给出一个步骤。
4. 长者可点击或说出“完成了”“再说一遍”“联系家人”。
5. 画面不清、标签不一致或没有明确确认时，系统不猜测，转入待家属查看。

### 家属闭环

1. 家属端只显示可解释事件，如“本人已口头确认”“标签需重新核对”。
2. 摘要明确区分用户确认、模型提示和家属操作。
3. 待办可由家属人工确认；没有医学或危险结论。

## 页面信息架构

```text
欢迎页
├─ 长者端：实时陪伴与当前任务
├─ 家属端：状态总览、事件时间线、日程、联系人
├─ 记忆中心
│  ├─ 人物与称呼
│  ├─ 药物与日程
│  ├─ 生活记忆
│  └─ 授权与数据
├─ 演示台：五步一镜到底场景
└─ 设置：Provider、接口、备份恢复
```

## 演示成功标准

- 观众能在 30 秒内理解对象、痛点和边界。
- 4 分钟内呈现主动提醒、视觉纠正、用户打断、记忆调用和家属协同。
- 无论真模型还是回放，界面都不伪造医学判断或“危险告警”。
- 网络或本地 NPU 不可用时，仍能完整展示业务链路，同时清楚标明不是模型输出。
