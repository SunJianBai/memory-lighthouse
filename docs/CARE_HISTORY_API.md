## 路径与权限

以下路径相对于 `/openBMB/api/v1`：

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| GET | `/households/:householdId/care-recipients/:recipientId/occurrences/history` | 提醒实例，按计划时间查询 |
| GET | `/households/:householdId/care-recipients/:recipientId/events/history` | 照护动态，按发生时间查询 |

使用现有 User Session，**每页**执行 `VIEW_EVENTS` 策略；不能用设备或管理员会话代替。家庭／长者组合必须有效，OWNER 和普通成员遵守原有不同的角色／授权规则。响应仍由统一 API envelope 包装，以下分页对象位于 `data`。

## 查询参数

| 参数 | 规则 |
| --- | --- |
| `startDate`、`endDate` | 同时提供或同时省略；真实 YYYY-MM-DD 日期，年份 1900–9998；结束日包含在内，先后有序，最多 31 个自然日 |
| `status` | 仅提醒接口：`DUE`、`AWAITING_CONFIRMATION`、`NEEDS_FAMILY_REVIEW`、`CONFIRMED`、`EXPIRED`；省略表示全部 |
| `limit` | 整数 1–50，默认 30；当前客户端固定 30 |
| `cursor` | 原样传回上页 `nextCursor`，最多 4096 字符；第一页省略，不传空字符串 |

传日期时按**当前长者档案时区**计算 UTC 半开窗口，不使用客户端本机时区。夏令时日可能为 23／25 小时，历史上被时区调整跳过的整日可产生空窗口。

省略日期时：提醒窗口为服务器当前时间前 24 小时至后 7×24 小时；动态无日期窗口，但每次仍只返回有限一页。31 天是单次指定日期的跨度，不是保留期，也不禁止查询更早月份。

## 分页响应

```json
{
  "items": [],
  "nextCursor": null,
  "timezone": "Asia/Shanghai",
  "from": "2026-08-31T16:00:00.000Z",
  "to": "2026-09-01T16:00:00.000Z"
}
```

- `items` 保持原 `OccurrenceView`／`CareEventView` 字段，不增加全文搜索或历史正文快照语义。
- `from/to` 是实际 UTC 查询窗口，前闭后开；无日期过滤的动态返回两个 null。
- `nextCursor` 为 null 表示本次查询已到末页；不返回全量总数，客户端显示“已加载 N 条”。
- 按对应时间降序、ID 降序续查；SQL 先过滤，再取 `limit + 1`，只解密／投影返回页。不会先全量下载再局部筛选。
- cursor 经过现有 AES-GCM 认证，包含专用用途版本，绑定家庭、长者、种类、时区、日期、状态、limit 及实际窗口。近期窗口在第一页固化，翻页不会随时钟漂移。
- 改任一条件或刷新时丢弃 cursor，从第一页重新查。当前档案时区变化、游标损坏或密钥轮换可能导致失效；400 后重新查询，不循环重试旧 cursor。

非法日期／参数／cursor 返回 400；401 为会话无效，403 为权限拒绝。列表读取异常不能转换为空结果。客户端后续页遇到 401/403/404 应清除受保护结果；普通网络失败可保留已加载项并重试。

## 数据语义与兼容

提醒状态是读取时的当前状态，正文来自当前日程。历史待核验项仍调用原 family-verify 命令，携带当前版本与幂等键；成功后用原筛选条件重新查询，已确认项退出待核验筛选。

各页不是跨请求的数据库快照：新记录刷新后可见，提醒状态改变也可能退出筛选。动态发生日期与提醒计划日期可以不同。未知／无记录不表示长者未行动，“已关闭”不表示已完成。

旧 `…/occurrences`、`…/events` 继续返回数组。没有删除或改写它们的契约，也不能据此声称旧调用者已全部受到新分页上限保护。
