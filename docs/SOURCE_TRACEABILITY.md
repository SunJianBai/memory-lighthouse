# 原方案追踪与实现取舍

本页把《守忆灯塔：基于 MiniCPM-o 4.5 全双工全模态能力的特等奖级创新应用赛题方案》中的核心主张映射到当前仓库，避免把提案中的建议、已实现能力和待硬件验证能力混在一起。

| 原方案主张 | 当前实现 | 验证边界 |
| --- | --- | --- |
| 持续看、持续听、主动说、可打断 | Realtime 音视频运行时、模型字幕/音频、转写命令和播放中断 | 公网音频会话已实测；本地真实摄像头待比赛设备复验 |
| 模型 + 规则引擎 | 日程调度和状态机决定业务状态；模型生成自然提醒 | 规则事件与模型输出分开记录，模型失败不写成“已提醒” |
| 服药提醒闭环 | 时间、药盒标签、位置、要求、提醒、明确确认、家属待办 | 不识别药片和剂量 |
| 厨房安全闭环 | 演示台提供“厨房离开前复核”场景，提示逐项确认 | 回放只模拟流水声；真模型必须依赖现场真实音视频，不由按钮伪造证据 |
| 夜间起身/跌倒风险 | 演示台提供“先开灯、坐稳、慢起身”低风险陪伴场景 | 不输出“检测到跌倒”，不从单帧或沉默判定危险 |
| 家属端通知与摘要 | 自动超时转待办、可解释事件、来源标记、人工确认关闭与回执、联系人电话 | 单机 Demo 使用同浏览器数据；生产版需要通知网关和账户 |
| 熟悉音色 | 随项目提供中性参考音，支持 Provider 自定义参考音 | 默认不克隆家属声音；公开分发前需确认参考音授权 |
| 隐私默认本地、分级上传 | 授权控制持久化、敏感上传、摄像头、麦克风和公网 Provider | 浏览器存储不是生产级加密数据库 |
| 延迟与稳定性指标 | 演示台显示首字、首音、视频帧和音频下溢 | 真模型连接时才显示真实值，回放保持“—/0” |
| 可复现材料 | 代码、配置示例、测试、模型文档、演示脚本、验收报告 | PPT 和最终录屏不在本仓库范围内 |

原方案对跌倒和厨房事件提出了较强的风险推断设想。当前实现主动收紧为“看见/听见线索后请求复核”：这减少了 Demo 的夸张感，但显著降低单帧误报、医疗化表述和错误告警的风险，也更容易在答辩现场解释和复现。
