# 原方案追踪与实现取舍

本页把《守忆灯塔：基于 MiniCPM-o 4.5 全双工全模态能力的特等奖级创新应用赛题方案》中的核心主张映射到当前仓库，避免把提案中的建议、已实现能力和待硬件验证能力混在一起。

| 原方案主张 | 当前实现 | 验证边界 |
| --- | --- | --- |
| 持续看、持续听、主动说、可打断 | 激活后的陪伴设备建立 Realtime 音视频会话，呈现模型字幕/音频并支持播放中断 | 公网音频会话已实测；真实摄像头仍需在目标 Android 设备复验 |
| 模型 + 规则引擎 | 服务端日程实例和客户端状态机决定业务状态；模型只负责自然提醒 | 规则事件与模型输出分开记录，模型失败不写成“已提醒” |
| 服药提醒闭环 | 家属录入时间、容器标签、位置和要求；设备提醒，长者明确确认，超时转家属待办 | 不识别药片和剂量 |
| 厨房安全闭环 | 家属将“离开厨房前逐项确认”配置为日程，陪伴端按执行窗口给出单步骤提示 | 不根据单帧或声音自动判定真实危险 |
| 夜间起身/跌倒风险 | 家属配置夜间陪伴步骤，设备只复述“先开灯、坐稳、慢起身”等低风险安排 | 不输出“检测到跌倒”，不从单帧或沉默判定危险 |
| 家属端通知与摘要 | 账号和家庭权限、自动超时转待办、可解释事件、来源标记、人工处理与回执 | 跨设备数据来自 Server API；远程关怀通话固定不录音、不转写 |
| 熟悉音色 | 随项目提供中性参考音，支持 Provider 自定义参考音 | 默认不克隆家属声音；公开分发前需确认参考音授权 |
| 隐私分级与最小必要 | MySQL 敏感正文加密、MinIO 受控对象、逐项 Consent、设备独立身份和管理员访问审计 | 公网模型处理、摄像头、麦克风与远程协助分别授权 |
| 延迟与稳定性指标 | Realtime 运行时保留首字、首音、视频帧和音频下溢指标，并显式呈现连接失败 | 指标只用于技术验收，不作为健康或危险判断 |
| 可复现材料 | 代码、配置示例、自动化测试、模型文档、部署脚本和验收报告 | PPT 和最终录屏不在本仓库范围内 |

原方案对跌倒和厨房事件提出了较强的风险推断设想。当前正式流程主动收紧为“执行家属确认过的日程步骤；不确定时请求本人或家属复核”，从源头降低单帧误报、医疗化表述和错误告警的风险。
