# 产品范围与角色

## 1. 重构目标

重构后的守忆灯塔不是把当前页面接到数据库，而是建立一个围绕家庭授权的完整闭环：家属维护可信资料和日程，陪伴设备在明确授权下调用 MiniCPM-o，确定性规则记录任务状态，家属能够查看、接手并在需要时发起实时音视频沟通。

核心目标：

1. 提供真实的注册、登录、会话撤销和账号恢复能力。
2. 一个用户可加入多个家庭，一个家庭可照护多个陪伴对象。
3. 一个 Web 和一个 Android App 按权限呈现家属工作区或陪伴模式，但服务器始终执行真正的权限校验。
4. 陪伴设备通过短时二维码或动态码激活，不长期保存激活家属的完整登录资格。
5. 家属可发起有强提示、可终止、可审计的远程音视频会话。
6. MySQL 成为业务事实源，Redis 仅保存可重建的短时状态，MinIO 保存对象内容。
7. MiniCPM-o 负责全模态理解和自然表达，不负责决定药物、危险、身份或任务完成状态。

## 2. 部署物而非角色页面

系统最终包含四个独立构建产物：

| 部署物 | 技术基线 | 包含内容 |
| --- | --- | --- |
| `server-api` | NestJS、Prisma | 所有业务 Module、REST、WebSocket、后台任务 |
| `admin-web` | Vue 3、Art Design Clean | 平台运营、开发检查和审计 |
| `client-web` | React、Vite | 登录、家属工作区、陪伴模式、远程通话 |
| `client-android` | Kotlin、Jetpack Compose | 登录、家属工作区、陪伴模式、原生音视频 |

“一个 Web/App 切换角色”只表示共用客户端壳和发布包，不表示权限合并：

- 家属页面根据 `Household Member` 和 `Care Authority` 开放。
- 陪伴模式必须选择已授权的 `Care Recipient`。
- 已激活设备可以进入锁定式陪伴模式，不暴露家属资料维护入口。
- 前端菜单隐藏不构成授权；每一个读取和写入都由服务器再次判断家庭范围。

## 3. 用户与使用场景

### 3.1 家属

- 注册或登录账号。
- 创建或加入家庭。
- 创建陪伴对象并邀请其他家属。
- 维护可信记忆、药盒标签、日程和联系人。
- 生成陪伴设备激活二维码或动态码。
- 查看陪伴事件、确认记录和待办。
- 对已授权且在线的陪伴设备发起远程陪伴。
- 管理授权、数据导出、设备撤销和账号安全。

### 3.2 陪伴对象

- 默认不需要单独账号。
- 在陪伴设备上看到一个主任务和少量明确操作。
- 主动开始或结束 MiniCPM-o 陪伴。
- 明确确认、要求重复或联系家属。
- 在远程音视频会话期间持续看到摄像头、麦克风和家属身份提示，并能立即结束会话。

### 3.3 平台管理员与开发检查员

- 管理用户状态、系统配置、模型 Provider 和运行健康度。
- 查看设备、绑定、通知和错误，不默认进入家庭内容。
- 开发阶段可基于 `Inspection Grant` 查看指定家庭的记忆及对话原文。
- 不能绕过家庭授权发起远程音视频，也不能获得陪伴设备媒体资格。

## 4. 功能矩阵

| 功能 | 家属模式 | 陪伴模式 | 管理员端 |
| --- | --- | --- | --- |
| 注册、登录、找回密码 | 是 | 首次配置时是 | 独立管理员登录 |
| 家庭与成员管理 | 是 | 否 | 元数据与冻结操作 |
| 陪伴对象档案 | 管理 | 只读最小快照 | 开发授权后检查 |
| 记忆、药物、日程 | 管理 | 按授权使用 | 开发授权后检查 |
| MiniCPM-o 全双工 | 可测试 | 核心能力 | 健康度与会话指标 |
| 事件、待办、确认 | 查看和处理 | 产生和本人确认 | 运维元数据 |
| 设备激活与撤销 | 发起和确认 | 完成激活 | 查看异常和强制撤销 |
| 远程音视频 | 发起 | 接收、提示、结束 | 只查看审计 |
| 原文检查 | 自有家庭 | 当前会话可见内容 | 仅开发检查授权 |

## 5. 明确不做

- 不做人脸身份认证。
- 不识别药片、剂量或疾病。
- 不把沉默、画面变化或模型推断自动升级成危险事件。
- 不允许管理员隐蔽打开家庭设备摄像头或麦克风。
- 不默认录制或长期保存远程音视频。
- 不把 Redis 作为业务事实源。
- 第一阶段不拆微服务，不引入分布式事务。

## 6. 关键业务规则

1. User 与 Care Recipient 是不同概念；陪伴对象可以没有账号。
2. 家属权限按 Household 和 Care Recipient 共同限定。
3. 激活码只能使用一次，成功或过期后不可恢复。
4. Device Identity 只能操作绑定的陪伴对象和允许的客户端能力。
5. Routine 是规则，Routine Occurrence 才是一次可确认的任务。
6. 只有用户明确回执或有权限家属回执才能形成 Confirmation。
7. 模型输出先是 Observation；确定性规则验证后才能形成 Care Event。
8. 远程音视频必须有独立 Remote Media Grant，普通家庭成员身份不自动授予。
9. 管理员内容检查与家庭正常读取采用不同 Interface，且必须写入 Audit Entry。
