# 隐私关键资产任务采用 MySQL 持久 Outbox

资产内容扫描和对象永久删除不是可丢失的短时作业：上传完成或删除请求与任务创建必须共同提交，且 Redis 整库丢失后仍要继续执行。因此这些任务使用 MySQL `outbox_events` 作为持久队列元数据，通过短事务、租约、尝试次数和下次可用时间认领；Worker 同时按资产状态周期补偿，避免单条投递故障永久卡住内容。

Redis 继续承担限流、在线状态、媒体排他租约，以及未来可重建的 Worker 唤醒/调度提示，但不保存资产扫描或删除的唯一任务事实。该选择增加少量数据库轮询，却避免“业务已提交而队列消息丢失”的双写窗口，也让数据库备份能够完整恢复待执行的隐私义务。若未来引入 BullMQ，只能把 Outbox ID 作为加速信号；消费者仍需以 MySQL 状态和租约为准并保持幂等。
