# Android 家属操作结果归属保护

- 基线提交：`ac04a51ca86a77818c5f94232c50ba16ee571947`
- 创建日期：2026-08-25
- 状态：DONE

## 问题

家属端在创建、编辑、删除或审批请求尚未返回时仍可切换家庭或长者。当前多数操作会把迟到的成功结果、错误和提示无条件写入当前 `LighthouseUiState`，因此旧家庭的记忆、日程、成员、授权或设备状态可能污染新页面。

## 范围

1. 建立可测试的 family operation owner，区分会话级、家庭级、长者级和精确选择级归属。
2. 接入家庭/长者创建，记忆与日程 CRUD，日程核验、待办、授权、成员角色、成员移除、照护权限、设备解绑和设备激活管理。
3. 修复手动选择长者时资源请求的旧错误与 loading 归属。
4. 已在服务器成功提交但作用域已经过期的操作不做客户端回滚；只禁止其覆盖新页面，下次刷新原作用域时读取权威结果。
5. 家庭/长者切换时清除与旧选择绑定的临时激活展示。

远程通话是跨页面持续的全局会话，不按当前家庭页面归属丢弃；陪伴设备动态码/二维码认领、远程通话生命周期和并发登录凭据原子提交另立阶段处理。

## 验收标准

1. 长者级操作在家庭、长者、用户或家属会话变化后，不写列表、提示或错误，也不占用新页面 loading。
2. 家庭级操作允许同一家庭内切换长者，但切换家庭或用户后不写回。
3. 精确选择级创建操作不得在用户切换选择后抢回焦点。
4. 当前作用域的成功与失败保持原有用户反馈。
5. 选择长者 A 后再选择 B，A 的资源成功或失败均不能覆盖 B，也不能提前清除 B 的 loading。
6. Android 目标测试以及 `testDebugUnitTest lintDebug assembleDebug` 全部通过。

## 实现步骤

1. 先用源码接线测试证明 mutation 尚未绑定 operation owner。
2. 新增纯 Kotlin operation context/owner 及行为测试。
3. 接入上述 mutation 和长者选择链，保留服务器提交语义。
4. 执行目标测试、完整 Android 门禁和独立并发复查。

## STOP 条件

- 需要改变服务器 API、数据库或远程通话生命周期语义。
- 无法区分安全的迟到服务器提交与不安全的当前页面写回。
- 既有 Android 门禁出现无法归因于本阶段改动的新失败。

## Execution notes

- 新增独立于 GET generation 的 `FamilyOperationCoordinator`，以会话、家庭、长者和精确选择 epoch 决定迟到操作是否仍可写入当前页面。
- 同一资源的编辑与删除采用 latest-per-lane；记忆和日程创建采用 additive，互不淘汰。即使退出后重新登录同一账号，旧 ticket 也不会恢复归属。
- 当前操作成功或失败后按需执行静默权威 GET；旧页面的成功、错误、提示和 busy 不再污染新选择，A→B→A 只允许重新拉取而不直接应用旧响应。
- 资源结果虽已过期，但同一登录会话收到 `SIGNED_OUT` 时仍会立即清除家属数据；旧登录会话的迟到鉴权错误不能终止新的登录。
- 家庭、长者、记忆、日程、核验、待办、同意、成员、照护权限、设备解绑和家属侧激活审批均已接入；日程核验的后续请求固定使用操作开始时捕获的家庭与长者。
- 日程、日程实例和待办在提交前校验所属长者；切换家庭或长者会关闭持有旧实体的对话框，自动回退选择也会清除旧激活凭据与审批详情。
- 权限更新触发的权威读取会淘汰更早的权限 GET，避免旧快照在 reconciliation 后反向覆盖新值。
- 真实 ViewModel 行为测试覆盖迟到成功/失败、权限旧读、自动选择回退、当前与过期会话 `SIGNED_OUT` 和同一用户退出重登；纯协调器及接线测试覆盖作用域、lane、additive、ABA、实体归属与 reconciliation。
- 验收：目标回归测试及 `testDebugUnitTest lintDebug assembleDebug` 全部通过，`git diff --check` 无错误。
- 后续阶段：陪伴设备认领轮询、远程通话跨会话结果归属和并发登录凭据提交仍需分别处理。
