# Android 显式登录会话所有权与跨账号结果隔离

- 基线提交：`e6e74793b347ff8a5751e7c07b2e527812892390`
- 创建日期：2026-08-25
- 状态：DONE

## 问题

Android 登录和注册会先清除当前凭据，网络返回后直接把新令牌写入全局安全存储，再通过全局会话请求 `me`。并发登录、登录后立即退出、或登录与切换到专用陪伴模式交错时，较早发出的迟到响应可能覆盖较新的账号，甚至在退出后重新恢复家属权限。登录、注册和邮箱验证的页面结果也没有绑定账号会话，旧请求可能把 busy、错误、用户信息或提示写进新账号页面。

## 本阶段范围

1. 为显式登录/注册建立 Repository 级会话 generation，登录响应只在仍拥有当前意图时才能写入安全存储。
2. 使用登录响应携带的 access token 直接读取 `me`，避免并发请求通过全局凭据读取另一个账号。
3. 退出、切入专用陪伴模式及终止用户会话时立即使在途登录/注册失效，迟到响应不得恢复本地权限。
4. 为 ViewModel 登录、注册和邮箱验证建立账号展示 epoch，旧 busy、成功、错误及用户刷新不得污染新会话。
5. 保持令牌刷新、设备凭据、家庭工作区和已完成的激活展示所有权行为不变。

## 明确排除

- 服务端登录、注册、刷新或邮箱验证码协议变更。
- 在服务端强制撤销已经返回但未被客户端采用的迟到会话。
- Web 管理端和 Web 家属端的认证重构。
- 登录与注册页面的视觉重构。

## 验收标准

1. 登录请求在退出后返回，不得把用户会话重新写入安全存储或把页面恢复为已登录。
2. 两个登录请求交错返回时，只有较新的请求可以提交令牌与用户；`me` 必须使用各自捕获的 access token。
3. 旧登录/注册失败不得覆盖较新登录的页面、错误或 busy 状态。
4. 旧账号的邮箱验证请求/确认在切换账号后不得更新新账号用户或提示。
5. 正常登录、注册、退出、邮箱验证与 refresh 行为保持可用。
6. Android 目标单测、完整单测、lint、debug 构建和 `git diff --check` 全部通过。

## 实现步骤

1. 增加可控 Deferred 回归，先复现迟到登录覆盖、退出后复活及旧页面结果污染。
2. 增加可测试的显式会话协调器并接入 Repository 的 begin/commit/invalidate 边界。
3. 将登录/注册的 `me` 获取绑定到响应令牌，并仅原子提交当前 generation。
4. 增加 ViewModel 认证展示 epoch，接入登录、注册、邮箱验证及所有登出边界。
5. 执行目标门禁、完整 Android 门禁和独立复审。

## STOP 条件

- 修复必须修改服务端 API、数据库或令牌格式。
- 无法在保持现有刷新语义的前提下原子隔离显式登录会话。
- Android 既有门禁出现无法归因于本阶段的新失败。

## 执行记录

- 先用可控 Deferred 用例复现并锁定：退出后迟到登录复活、旧登录覆盖新登录、旧认证错误污染新会话、旧账号 401 使用新账号令牌重试、终止 refresh 恢复误报、过期 access 退出未完成服务端撤销、慢退出未先释放媒体，以及锁定陪伴模式遗留 busy。
- 新增 Repository 级显式会话 generation。登录/注册的 `me` 固定使用响应携带的 access token；会话、用户命名空间和 refresh 结果仅由当前 generation 提交。
- 将普通用户请求从首次发送到 401 refresh/retry 全程绑定同一 generation，旧账号请求不能跨到新账号令牌；终止 refresh 只清理仍属于自己的本地会话。
- 退出改为两阶段撤权：同步捕获并清除旧用户权限，立即释放家属/陪伴端本地媒体，再以捕获令牌尽力结束家庭远程会话和服务端登录会话；迟到的旧撤销不会清除期间建立的新登录。
- 新增 ViewModel 认证展示 epoch，覆盖登录、注册、邮箱验证码、恢复、角色切换和锁定陪伴模式，旧 busy、错误、成功和用户结果不会污染新认证边界。
- 退出完成后只按当前设备凭据决定是否回到锁定陪伴模式，覆盖凭据在网络等待期间 `true -> false` 的失效竞态；已激活设备退出也会结束捕获的家属远程会话。
- 独立复审提出的 P0/P1/P2 均已通过新增回归关闭，最终复审未发现剩余 P0/P1/P2。
- 最终门禁：Android `testDebugUnitTest` 共 193 项、0 失败/0 跳过；`lintDebug`、`assembleDebug` 和 `git diff --check` 全部通过。
